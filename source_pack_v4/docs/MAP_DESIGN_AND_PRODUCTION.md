## 1. 지금 이상하게 보이는 이유

- Downloads의 ROOTS_TERRACE_BLOCKOUT_V01은 독립된 한 맵의 경로 시험이다. 실제 게임의 전체 지역이나 배경 완성안이 아니다.

- 다만 공통 ENTRY/EXIT/CLUES와 비슷한 적 무리 좌표를 재사용한다. 장소별 차이를 소품과 일부 지형으로 처리하는 구조는 계속 맵을 늘릴 때 제약이 된다.
- 이전 START_PARALLEL_WORK 작업A에서 각 지역에 같은 ‘입구→갈림→전투→발견→재합류’ 순서를 요구했다. 설계 초반부터 형태를 과도하게 제한했다. 모든 맵에 두 길과 지름길이 필요한 것은 아니다.
- 이번 화면은 고저차가 실제로 있지만 넓은 단색 면, 거의 대칭인 두 띠, 길게 선 중앙벽, 약한 명암/단차 단서 때문에 평면적으로 읽힌다. 높이만 더 올리거나 장식만 더해 해결할 문제는 아니다.

| 단위 | 뜻 | 이번 게임의 예 |
|---|---|---|
| 세계 | 여러 문화권/여행 지역 사이의 큰 연결 | 본편 여행 전체. 지금 전부 제작하지 않음 |
| 지역 | 지리·문화·환경 자산을 공유하는 장소 묶음 | 열대/몬순 숲과 오래된 수로·석조 유적 |
| 맵 | 입출구, 지형, 전투·발견과 상태를 가진 플레이 공간 | 물길 입구, 뿌리의 단상, 얼굴 사원 |
| 장면 구성 구간 | 한 맵 안에서 시야·행동이 달라지는 부분 | 물가 굽이, 오르막, 전투 마당, 전망 |
| 경로 | 구간을 연결하는 실제 이동 선택 | 주경로, 선택 샛길, 의미 있는 귀환길 |

세 장소는 우선 **첫 지역 안의 세 맵**으로 부른다. 문화권 세 개로 확대하지 않는다. 맵이 여러 화면에 걸쳐 보여도 한 맵이고, 길이 갈라져도 자동으로 별도 맵이 되지 않는다.

## 3. 기본 구조 권고

수작업으로 설계한 여러 맵을 출입구로 연결한다. 한 맵 안에서는 8방향으로 자유롭게 이동한다. 데모의 연결 초안:

```text
물길 입구 ⇄ 뿌리의 단상 ⇄ 얼굴 사원
                           └ 다음 여정의 단서 / 데모 마무리
```

이것은 연결 관계이며, 모든 맵을 남쪽 입장·북쪽 퇴장으로 만들라는 배치도가 아니다. 연결 위치는 수로 굽이·숲 틈·석문 같은 지형으로 납득시킨다. 입출구 주변에는 안전한 착지 공간과 이동 방향을 이어 주는 짧은 여유 구간을 둔다.

장소가 달라지는 경계와 제작/실행 단위를 맞추는 것을 기본으로 한다. 매 화면마다 로딩하거나 한 맵 안의 모든 전투장을 분리하지 않는다. 출입구는 도착 맵의 특정 출입구에 연결하며, 돌아오면 같은 연결 지점 근처에 나온다. 접근 후 F로 이동하는 현행 방식을 초기 검토값으로 유지한다.

맵 수는 고정 분량 목표가 아니다. 우선 한 맵을 제대로 만들고 이웃 맵과 연결해 본 뒤 크기와 밀도를 조정한다. 본편 전체 맵 수·월드맵 UI·랜덤 생성은 이번에 확정하지 않는다.

## 4. 세 맵은 서로 다른 공간 문법을 쓴다

| 맵 | 기억할 행동 | 큰 지형/실루엣 | 경로의 성격 | 출입구 제안 |
|---|---|---|---|---|
| 물길 입구 | 물가 굽이를 따라가며 숲 안쪽으로 들어간다 | 비대칭 물웅덩이/수로, 굽은 둑, 열린 사냥터 | 읽기 쉬운 주경로 + 짧은 발견 샛길. 두 갈래 의무 없음 | 남서 진입 → 동쪽 숲 틈 |
| 뿌리의 단상 | 아래에서 본 큰 뿌리와 단상에 올라 주변을 내려다본다 | 아래 마당·측면 오르막·위쪽 단상, 한쪽의 큰 뿌리 덩어리 | 상승 동선이 중심. 선택 우회는 실제 접근 차이가 있을 때만 | 서쪽 하단 진입 → 북동 상단 석문 |
| 얼굴 사원 | 좁은 접근부를 지나 열린 사원 앞마당에 들어선다 | 가려졌다 드러나는 사원 얼굴, 회랑, 넓은 마당 | 압축된 접근 → 넓은 전투/발견 → 마무리. 갈림 의무 없음 | 남서 접근 → 내부 흔적/끝 지점 |

원거리로 다음 장소를 예고할 수 있으나 모든 맵에서 종착지가 입구부터 보여야 하는 것은 아니다. 첫 화면에는 적어도 다음에 걸어갈 방향이 보여야 한다. 실제 문화·서사 사건은 STORY_CANON의 확정 범위를 넘겨 고정하지 않는다.

## 5. 첫 실제 제작 대상 — 물길 입구

뿌리 블록아웃을 전체 맵의 템플릿으로 복제하지 않는다. 첫 맵은 기본 이동·전투·환경 제작을 검증하기 쉬운 물길 입구로 제안한다.

### 공간 구성

1. 남서 입구: 플레이어와 이동할 둑길이 즉시 보이는 작은 여유 공간.
2. 굽은 물가: 물을 피해서 이동할 이유가 있는 비대칭 경계. 한 덩어리의 수역과 경로가 화면에서 읽힌다.
3. 넓어진 둑 위 마당: 자동마법으로 무리를 상대하며 옆으로 회피할 공간. 반복 나무로 전투 바닥을 채우지 않는다.
4. 물가의 짧은 샛길: 선택 발견. 주경로 진행과 모든 선택 발견을 강제로 묶는 현행 공통 게이트는 별도 재검토한다. 이번 문서만으로 저장/진행을 변경하지 않는다.
5. 동쪽 숲 틈: 다음 맵 출구. 물길을 돌아 올라왔다는 높이·풍경 변화가 읽힌다.

초기 배치 예산은 대략 폭45~60u/깊이35~50u 범위에서 지형을 놓고 정상 카메라로 줄이거나 늘린다. 고정 사양이나 플레이 시간 보장이 아니다. 이동 속도가 7.5~10u/s라 빈 공간을 크게 만들면 금방 통과하거나 지루해진다. 전투 수·체력·왕복을 늘려 8~12분을 맞추지 않는다. 세 맵 총 초행 시간은 사람 플레이로 나중에 측정한다.

### 첫 실행 결과물의 범위

- 물길 입구의 전체 플레이 가능한 지형/경계/주경로/선택 샛길.
- 뿌리의 단상 **입구 부분만** 연결 확인용으로 제작. 두 번째 맵 전체 완성으로 보고하지 않는다.
- 양쪽 출입구 왕복, 도착 방향·안전한 spawn·즉시 재전이 방지.
- 대표 구간 한 화면에 B′ 환경 재질/물가/식생/석조를 적용해 최종 화면 방향 비교.
- 캐릭터 담당과 분리된 검토 장면으로 제작하며 승인 정지8방향 또는 크기를 맞춘 대체물을 사용. 캐릭터 원화/모션 파일을 다시 만들지 않는다.
- 전투 결합 단계에서는 기존 Player·적·자동/직접마법을 재사용한다. 새 임시 대시나 새 전투 수치로 체감을 대신하지 않는다.

## 6. 배경은 무엇을 어떻게 만드는가

**수작업 배치 + 재사용 환경 부품 + 맵별 대표물**을 기본으로 한다. 전체 배경 한 장을 통째로 이미지로 만들어 충돌 위에 얹는 방식은 이동·높이·가림·수정에 불리하다.

| 구성 | 제작 방식 | 검토 기준 |
|---|---|---|
| 바닥/단차/오르막 | 기존 단일 불투명 지형과 동일 높이/삼각형 충돌 | 보이는 높이와 발·적·경고·복원 위치 일치 |
| 흙/풀/젖은 돌/물 | 작은 공통 재질 묶음과 지형 내부 마스크 | 바닥은 캐릭터/위험 표시보다 낮은 시각적 밀도 |
| 석축/큰 바위/계단 옆면 | 실제 부피가 필요한 단순 mesh 부품 | 측면과 명암으로 단차가 읽히며 통과 불가능 경계가 보임 |
| 수풀/잎/작은 자연물 | B′ 스타일 투명 카드·소량 변형 | alpha·원근·광원 일치, 가림 처리와 반복무늬 확인 |
| 사원/큰 뿌리 등 대표물 | 공간 역할을 먼저 잡고 카드/mesh 혼합 결정 | 한 맵을 기억하게 하는 큰 형태, 충돌과 시야 검토 |
| 멀리 보이는 풍경 | 충돌 없는 먼 배경/실루엣 | 갈 수 있는 공간과 혼동하지 않으며 같은 지역의 연속성 유지 |

최초 환경 묶음은 지면3종 정도, 물가 전이, 석축 직선/모서리/끝, 바위 큰/작은, 식생 낮은/높은, 지역 대표물 하나로 시작한다. 목록과 수량은 제작 예산 초안이다. 한 화면 통합 후 부족한 부품만 추가한다. 수채/페인터리 질감을 다시 도입하지 않는다.

평면감은 큰 높이 차 하나, 드러나는 단차 옆면, 경사 방향, 발 그림자, 원중근경과 가림으로 점검한다. 장식 밀도와 어두운 그림자만 늘리면 전투 가독성이 나빠진다. 고저차는 통행/시야 차이부터 설계하며 고지대 피해보너스 같은 새 규칙은 자동 추가하지 않는다.

현행 높이장은 같은 x,z에 하나의 걸을 수 있는 높이를 제공한다. 다리 위/아래를 동시에 걷거나 다층 실내를 만들려면 이동·AI·경고·저장 높이 계약을 별도로 확장해야 한다. 이번 데모는 경사·단상으로 입체감을 만들고 겹치는 통행층은 도입하지 않는다.

## 7. 계속 만들기 위한 제작 자료와 코드 경계

맵마다 한 장 분량의 설계표를 작성한다: 맵ID/지역ID, 한 문장 역할, 인접 맵과 출입구ID, 주경로/선택 경로, 높이 단면, 주요 카메라 장면, 전투 위치·역할, 발견·영구상태, 필요한 환경 부품, 수용 기준.

출입구 데이터 계약(첫 두 맵에 map_id / exit_id / destination_entry / entries 적용):

```text
map_id: water_entry
exit_id: east_forest
destination_map: roots_terrace
destination_entry: west_low
arrival: 안전한 위치 + 바라볼 방향
```

- 공통 게임 시스템은 이동/전투/카메라/저장/전이를 담당한다.
- 맵별 데이터/씬은 지형·장식·적 배치·발견·출입구를 담당한다. Godot 편집기에서 배치 확인 가능한 씬을 지향하되 지형 생성과 높이 조회는 같은 정의에서 나온다.
- 현재 chapter==0/1/2의 하드코딩과 전역 Landscape.lab_region은 현행 구현이다. 첫 맵 연결 시험에서 필요한 범위부터 map_id/entry_id 경계를 만든다. 전체 엔진을 한 번에 다시 쓰지 않는다.
- 발견/열린 길/적 상태는 map_id 아래 안정적인 개체ID로 저장하는 방향이다. 기존 journey_v2 저장의 이행 정책 없이 운영 저장 형식을 바꾸지 않는다. 실험은 --test 또는 별도 프로필만 사용한다.
- 기존 미니맵의 ‘전체 지형 + 발견물’ 범위를 유지한다. 새 맵 외곽/출입구·경로 데이터와 맞는지 검사한다.
- 맵 전환 시 현재 상태 보관 → 목적 맵 생성 → 해당 상태 복원 → 지정 출입구의 안전 위치에 배치 → 카메라 맞춤 순서로 검증한다. 돌아왔을 때 맵의 열린 길과 발견이 유지되어야 한다.

## 8. 제작 순서와 통과 기준

1. **설계**: 맵 연결도 + 첫 맵 평면/높이 단면 + 정상 카메라 주요 장면 + 환경 부품 목록. 모든 맵에 같은 갈림길을 요구하지 않는다.
2. **실제 지형**: 물길 입구를 실제 크기로 만들고 이웃 입구와 왕복. 충돌·발 접촉·카메라·경계를 실제 물리 입력과 GPU 화면으로 검증.
3. **환경 대표 화면**: 주인공 약74px/카메라52도·size22에서 지면·석축·물·식생을 함께 확인. 확대 컨셉 그림으로 대체하지 않는다.
4. **전투와 발견**: 실제 기존 AI/마법을 배치해 통행·몰이·회피·경고·가림 확인. 사람 체감 미통과를 자동 테스트 통과로 대신하지 않는다.
5. **전환과 복귀**: 왕복·종료·재실행·열린 길/발견/개체 상태 복원 확인. 새 테스트 프로필로 검사한다.
6. **반복 제작 검증**: 같은 부품/공통 기능으로 두 번째 맵을 다른 지형으로 제작. 추가 부품·특수 코드·작업시간·수정 횟수를 기록한 후 나머지 맵 범위를 잡는다.

수용 질문: 첫 화면에서 갈 방향이 보이는가? 안내문 없이 다른 두 장소를 구별하는가? 지름길은 실제 이동을 줄이는가? 캐릭터/경고가 배경에 묻히지 않는가? 이전 맵으로 돌아와도 성과가 남는가? 다음 맵 제작 때 공통 시스템을 복제하지 않아도 되는가?

## 9. 병행 작업 인계

캐릭터 축: 승인 원화/최종8방향/접지·모션·손VFX. 맵 축: 연결도/지형/환경 부품/실제 배치/출입구. 공유 기준은 카메라·캐릭터 실제크기·발 높이·이동속도·B′ 스타일·가림이다.

다른 작업에 전달할 범위:

> MAP_DESIGN_AND_PRODUCTION.md와 GAME_PROJECT_SOURCE.md를 읽고 물길 입구의 설계안을 구체화한다. 맵 연결도, 평면과 높이 단면, 정상 카메라 주요 장면3개, 환경 부품 목록을 제출한다. 두 경로·재합류·지름길을 일률적으로 넣지 않는다. 캐릭터 파일과 현행상태를 수정하지 않는다. 독립 블록아웃만 만들었다면 본게임 통합이나 배경 완성으로 보고하지 않는다. 구현 단계에서는 첫 맵과 이웃 맵 입구의 실제 왕복을 포함하고, 원본 겜1/사용자 저장은 사용하지 않는다.

온라인 작업 생성/메시지 전송은 수행하지 않았다. 사용자 후속 승인에 따른 실제 제작 결과는 maps/README.md와 WORK_LOG에 기록한다. 본게임 전투/운영 저장 통합 및 최종 미술 승인은 별도 단계다.

## 2026-09-25 — 제작 순서 정정

사용자 의도는 위 블록아웃을 먼저 보고 고르는 것이 아니라, 캐릭터 제작처럼 **완성 화면 컨셉 → 문법 → 기초 자산 → 실제 한 화면 → 완성/확장** 순으로 맵을 개발하는 것이다. `composition_proof`는 기능 실험 기록으로만 남기고 시각 목표나 다음 제작 기준으로 사용하지 않는다.

첫 논의용 목표 화면은 [숲 수로 성소 컨셉](design_refs/map_concept_v1/README.md)이다. 캐릭터·적·UI를 제외하고 연속 지형, 사선 수로, 높이층, 전투 여백, 뿌리 성소의 화면 관계를 제안한다. 사용자 승인 전에는 이 한 장의 다리·계단·구조물 배치를 전역 문법으로 일반화하거나 자산 제작에 착수하지 않는다. 첨부 `MAP_GRAMMAR_v1`은 유효한 용어가 있는 참고 입력이지만 그 문서의 순서와 규칙을 자동 채택하지 않는다.

## 2026-09-25 — v2 이후 실제 맵 제작 게이트

[v2 North Star](design_refs/map_concept_v2/README.md)는 한 화면의 최종 배치도가 아니라 **한 맵 안의 대표적인 큰 구간을 멀리서 본 조감 시안**으로 취급한다. 실제 플레이에서는 약 74px 주인공과 전투 가독성을 유지하는 더 가까운 카메라가 플레이어를 따라가며 이 구간의 일부를 보여준다. 따라서 시안의 정확한 길·수로·기둥·계단 위치는 채택하지 않고, 다음 상위 관계만 잠정 기준으로 남긴다.

- 높은 고정 사선 정사영과 충분히 보이는 바닥 윗면
- 큰 연속 지형, 사선 수로, 단계적으로 드러나는 고지 랜드마크
- 이동·전투 바닥은 조용하게, 경계·단차·랜드마크에 정보와 밀도 집중
- 주인공보다 약한 대비와 큰 덩어리 위주의 환경 형태
- 작은 공통 자산군을 배치·겹침·색·지형 관계로 변주

이 단계에서 전체 장면을 더 예쁘게 만드는 ImageGen 반복은 중단한다. 이후 컨셉 이미지는 `특정 랜드마크`, `한 재료군`, `가림 해결`처럼 엔진 화면에서 답하지 못한 한 가지 질문이 있을 때만 만든다. 전체 시안을 반복해서 미화하는 것은 동선·충돌·카메라·전투 문제를 검증하지 못하므로 제작 진척으로 세지 않는다.

다음 제작은 네 개의 게이트로 진행한다.

1. **MAP_SPEC**: 첫 맵의 한 문장 경험, 입구/출구, 이동 리듬, 높이 단면, 보였다가 가려지고 다시 보이는 랜드마크, 전투 위치의 공간 역할을 한 장에 확정한다. 전역 자산 수량 공식은 두지 않는다.
2. **실제 크기 그레이박스**: Godot에서 승인 주인공 크기, 실제 이동/회피/공격, 카메라 추적을 사용한다. 기존 임시 지형의 기술 기반은 재사용하되 기존 배치와 미술은 답으로 삼지 않는다. 새 배경 자산은 아직 만들지 않는다.
3. **대표 플레이 화면 아트 슬라이스**: 그레이박스에서 가장 중요한 한 화면에만 지면/경계/계단·다리/물/식생 덩어리/대표 랜드마크 자산군을 적용한다. 필요한 부품은 이 화면에서 역산하며 임의의 종류 수를 먼저 채우지 않는다.
4. **맵 확장**: 실제 캐릭터·적·VFX가 배경에 묻히지 않고, 길 찾기·가림·회피 공간이 사람 검수에 통과한 뒤 같은 자산군으로 나머지 구간을 확장한다.

첫 숲 수로 맵의 맵별 가설은 `침수된 수로를 따라 무너진 단구를 돌아 뿌리에 잠긴 성소에 이른다`이다. 후보 리듬은 `물가 입구 → 방향을 바꾸는 수로변 → 열린 석조 마당 → 성소의 부분 노출 → 계단 상승 → 성소 접근`이다. 직사각 마당과 직각 굽이를 허용하며, 곡선과 비대칭을 의무화하지 않는다. H0 수로, H1 주동선, H2 성소 접근을 쓰되 위아래 통행이 겹치는 다층 구조는 만들지 않는다. 샛길은 형식적으로 강제하지 않는다.

구조 검수 기준은 실제 플레이 화면에서 이동 방향과 높이 연결이 읽히고, 벽·식생이 캐릭터와 위험 표시를 가리지 않으며, 회피와 다수전 이동 폭이 충분한 것이다. 직사각형이라는 이유로 탈락시키지 않는다. 별도로 North Star의 구조·재료·밀도와 실제 화면을 비교한다. 기능 통과는 시각 통과를 대신하지 않는다.

사용자 후속 정의로 첫 맵은 [세 막의 순례 MAP_SPEC](maps/FIRST_FOREST_WATERWAY_MAP_SPEC.md)으로 구체화했다. `물가 입구`는 신비롭고 성스러운 유적의 문턱, `굽이치는 강가`는 선택 구간이 아닌 강을 따라 실제로 상승하는 긴 길, `뿌리 성소`는 거대한 나무뿌리에 덮인 고대 동남아 성소다. 세 막은 별도 로딩 맵이 아니라 하나의 연속 지형이다. 첫 실제 검증은 별도 `forest_pilgrimage_graybox`이며 기존 composition_proof 배치는 사용하지 않는다.
