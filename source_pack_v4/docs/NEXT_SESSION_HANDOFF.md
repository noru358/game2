1. 첨부 파일 목록을 실제로 확인한다. ZIP을 열 수 있으면 `PACKAGE_MANIFEST.json`, 이 문서, 통합 정본 CURRENT/NEXT, AGENTS를 읽는다. 파일 접근/압축 해제/이미지 열람/게임 실행 중 가능한 기능과 불가능한 기능을 구분한다.
2. `experiments/terrace/project.godot`, `game/player.gd`, `lab/journey.tscn`, `tests/core_response.gd`와 디자인 PNG19개가 실제로 있는지 확인한다. 문서에 경로가 적혀 있다는 이유만으로 소스 보유를 주장하지 않는다.
3. 최신8개는 design_refs/ASSET_MANIFEST.json의 gallery_individual_order로 식별한다.4번은 `file_000000000cf88211bec5b54d1b75e86e.png`다. 이름만으로 방향을 추정하지 말고 이미지를 연다.
4. 이번 목표/작업축/완료 조건을 짧게 말하고 첫 작업을 시작한다. 전체 기획을 다시 물어보거나 오래된 G1 이미지0/HOLD를 되살리지 않는다.

## 현재 위치

최종 목표는 본편 Steam 출시와 초기 안정화. P1 핵심 경험 검증이 중심이고 P2 대표 데모 일부 구현, 현재 M1-A 이동/전투 기본 품질이다. G1은 방향 사용자 승인, G2 모델 동일성 고정은 미완료. Packet1A는0.10 부분 구현이며 사람 체감/실청음 미승인, Packet2는 대기다.

## 첫 작업 A — 디자인:4번 개별 PNG 수리

- 입력: 최신 개별8장과 검수 시트, 승인 대표4방향/주인공 콘셉트. 원본 목록에서 정확한 파일을 열어 비교한다.
- 확인된 문제:4번은 몸의 후면 방향과 측면으로 돌아간 얼굴의 대응이 어긋난 것으로 관찰됐다. 실제 픽셀을 다시 보고 수정 부위를 확정한다.
- 유지: 나머지7개 원본, B′ 클린2.5D, 사막여우 큰 귀/꼬리, 아이보리·남청·금·청색 보석, 눈썹/작은 입, 폐쇄형 검정 신발, 손 시전. 지팡이/등 두루마리 없음.
- 납품: **수정된4번 개별 투명 PNG**. 원본을 덮지 말고 새 버전 파일로 내며 전체 시트만 내놓고 끝내지 않는다. 기존 개별 캔버스1254×1254/투명 배경, 캐릭터 크기·발 위치·방향 동일성을 검사한다. 생성 도구의 출력이 규격과 다르면 그대로 통과시키지 않는다.
- 종료 조건: 실제 이미지 비교와 규격 확인 후 사용자 수용. 사용자가 수용하기 전 G2 통과나 모션 양산 완료로 기록하지 않는다.
- 도구가 없거나 첨부 이미지를 열 수 없으면 그 제한을 명시한다. 새 캐릭터를 추측해 그리지 말고 필요한 정확한 PNG를 요청하거나 접근 가능한 게임성 검토를 진행한다.

## 첫 작업 B — 게임성: Packet1A 사람 검수

- 입력: 현행0.10 코드와 D112 검수 기록. 달리기 도달1.8→0.75초/상쇄입력 제자리가속 제거/공격 탭1회 예약은 이미 구현됐으므로 다시 구현하지 않는다.
- 사람이 확인할 것: 정지/반전, 자동공격으로 무리 정리, 직접3연타 리듬/개입 이유, 밀치기의 공간 회복, 회피의 구분, 타격과 실제 소리,5~10분 피로도.
- 각 항목을 `상황 → 관찰 → 기대 → 수정 필요 여부`로 기록한다. 문제와 기대가 확인된 범위만 조정한다. 기능/성능 검사 통과를 손맛 승인으로 대신하지 않는다.
- 게임 실행 가능한 환경에서는 독립 --test와 분리 저장을 사용한다. 사용자 게임을 종료하거나 실제 저장을 시험에 쓰지 않는다. 설치 의존성은 MIGRATION_VERIFICATION을 따른다.
- 실행할 수 없는 환경에서는 D112 기록의 한계를 설명하고 위 항목으로 사용자 플레이 관찰을 받는다. 실행/실청음을 했다고 주장하지 않는다.

A/B는 작업축 병행이며 다중 에이전트 실행 지시가 아니다. 이미지 생성/수정 가능한 환경이라면 A를 첫 기본 작업으로 시작하고, 게임성 검수는 별도로 이어간다.

## 매 작업 끝

통합 정본 CURRENT/NEXT/CHANGELOG와 WORK_LOG·DISCUSSION_LOG를 갱신한다. 결정 변경은 DECISION_HISTORY, 이야기 변경은 STORY_CANON에도 반영한다. `실제 변경 / 자동검사 / 픽셀·모션검사 / 사람 수용 / 남은 문제 / 다음 작업`을 구분한다.

해당 환경에서 파일을 직접 저장/교체할 수 없으면 수정본 파일 또는 정확한 변경문을 산출하고 사용자가 교체할 항목을 지정한다. 다른 대화/업로드본이 자동으로 갱신된다고 말하지 않는다. 작업 종료 후 결과 증거를 보존하고 해당 작업의 임시 복사본만 정리한다.
