# 본편까지의 단계 정의

현재 단계/다음 작업은 [현재 게임 기준](GAME_PROJECT_SOURCE.md)을 따른다. 여기서는 단계 정의와 통과조건만 유지한다.

## 전체 단계와 완성되어야 할 것

| 단계 | 완성물 | 다음 단계로 갈 근거 |
|---|---|---|
| P0 본편 기준 정렬 | 핵심 약속, 세계·성장·중단복귀 구조, 최소 서사, 범위 상한/미정 목록 | 확정 방향끼리 충돌 없음. 중요한 미정의 결정 시점과 담당이 정해짐 |
| P1 핵심 경험 검증 | 작은 구간에서 이동·자동/직접 마법·지형 탐험·성장 비교 | 실제 사람이 공격/위험/길을 이해하고 탐험·전투를 즐기는지 관찰. 실패하면 콘텐츠 양으로 덮지 않음 |
| P2 대표 데모 완성 | 약10분 시작→전투→강화→탐험→핵심 충돌→성과, 대표 미술/음향/UI/저장 | 초행 플레이의 재미·가독성·시간·중단복귀 확인. 본편 제작 샘플로 쓸 품질 |
| P3 공개 데모·외부 검증 | 고정 후보 빌드, 다른 PC 검수, 본편 상점+데모 앱, 소개/영상/출처, Steam 설치/심사/공개 | 실제 외부 설치·플레이와 피드백 확보. 공개 완료와 반응의 긍정/부정은 별개 |
| P4 본편 범위·생산성 확정 | 캠페인/지역 연결, 주요 성장·사건·결말, 포함/제외 범위, 제작 실측 기반 일정·예산 | 대표구간 제작비와 외부 반응으로 현실적인 본편 범위를 사용자와 확정 |
| P5 본편 전체 구현(Alpha) | 출시 범위의 모든 필수 시스템·지역·선택 콘텐츠·사건·결말 연결 | 새 게임부터 정상 플레이/저장으로 끝까지 완주. 후반 분량 공백 없음 |
| P6 품질 마감(Beta/RC) | 전체 미술/음향/UI, 밸런스·성능·저장 이행, 장치별 검사, 고정 출시 후보/롤백 | 진행 불가·저장 손상·치명적 크래시 해결. 지원 약속과 실제 제품 일치 |
| P7 Steam 본편 출시 | 가격/상점/지원/빌드/공개 설정과 사용자 승인, 실제 출시 | 이용자 획득·설치·실행·저장 경로 검증. 심사 완료와 공개 실행을 구분 |
| P8 초기 안정화 | 이슈 접수·재현·핫픽스·회귀·패치 안내, 반응 분석 | 치명적 문제가 통제되고 유지보수/후속 업데이트 범위를 결정 |

단계는 작업 의존 관계이지 날짜 약속이 아니다. P0의 계획 초안은 지금부터 유지하고 P4에서 실측으로 확정한다. 테스트 수나 D번호로 완성률을 계산하지 않는다.

## 현재 데모의 닫을 순서

1. **M1-A 전투·공간 기본 품질:** 처치 부하 전후 동일 조건 측정. 손/효과가 8방향·3타에서 맞고 전신 흔들기로 타격을 대체하지 않음. 원경은 고정 상단 띠가 아니라 지형·카메라·가림에 맞게 배치.
2. **M1-B 세 장소의 고유 경험:** 물길의 우회와 물가 전투, 정글의 오르막/전망/지름길, 사원 회랑과 마지막 충돌. 같은 배치에 소품만 바꾸지 않음. 기존 범위 내에서 구성.
3. **M1-C 전체 초회 플레이:** 외부 설명 없이 시작→강화→발견→종료. 실제 소요시간/막힘/휴식/다음 여행 기대를 기록. 적 체력·빈 이동·강제 대기로 시간을 채우지 않음.
4. **M1-D 대표 품질과 공개 후보:** 검증된 경험의 미술·소리·안내·설정·메뉴 마감, 다른 PC/세이브/배포 검사. 이어 P3의 Steam 준비·외부 플레이.

M1-A 자동 검사가 통과해도 사용자 조작감/연속 모션 평가는 별도로 남긴다. 디테일 요청을 해결할 때 위 순서에서 위치를 명시하고, 새 아이디어는 필수/후속/보류로 분리한다.

## 병행 관리와 미정의 결정 시점

- 총괄(에이전트): 매 묶음 범위·원인·구현·검증·한계·다음 작업을 기록하고, 현재 단계의 실패/미검증 항목에 우선순위를 둔다.
- 사용자: 주요 경험의 수용 판단, 본편 규모/비용/지원/가격/외부 공개 결정. 이전 답변은 반복 확인하지 않는다.
- 이야기: 현재 STORY_CANON을 보존하고 새 공간 경험과의 적합성을 검토. 첨부의 ‘줄거리 재검토’를 근거로 채택된 이야기나 결말을 자동 폐기하지 않는다. 데모 도입·작은 성과는 P2, 캠페인 전환·종결은 P4까지 구체화.
- 예산/일정: P2부터 자산·구현·통합·검수/재작업 비용을 실측. P4에서 범위/일정을 사용자와 확정. 근거 없는 출시일은 만들지 않는다.
- 지원 범위: 현 작업은 한국어 Windows/키보드 중심. 영어·패드·Mac·Steam Deck·도전과제·클라우드는 자동 약속하지 않으며 P3/P4 이전에 목적과 비용을 결정.
- 자산 출처/생성 AI: 받을 때부터 기록. 상점/제품 제출 전 실제 사용 자산과 설문을 대조.
- Steam/홍보: 대표 화면과 제품 설명을 준비할 수 있는 시점부터 병행. 계정/앱/지출/공개는 실제 권한과 사용자 승인 범위에서 수행.
