# 고정 시점 비교와 제작 비용 — 2026-09-24

## 이번 결과

사용자가 0°·20°·45° 실제 전투 비교를 승인하고 GPT-5.6 Sol ‘아주 높음’으로 이어갈 때의 구현 난이도·비용을 고려해 달라고 요청했다. 이 문서는 그 운영 조건에 대한 설계 판단이며 Sol로 이번 작업을 실행·측정했다는 뜻은 아니다. 모델 설정을 바꾸거나 별도 에이전트를 실행하지 않았다.

`experiments/terrace/maps/view_compare.tscn -- --test`가 비교 장면이다. 작업공간의 `PLAY_VIEW_COMPARISON.cmd`로 실행한다. 처음에는 같은 8마리 배치를 정지 상태로 보여준다.

| 키 | 기능 |
|---|---|
| 1 / 2 / 3 | 0° / 20° / 45° 전환. 전투 상태·위치 보존 |
| F | 전투 정지·재개. 같은 순간을 다른 시점으로 비교 |
| R | 같은 위치·체력·적 배치로 전투 재시작 |
| N | 8마리 / 24마리 전환 후 재시작 |
| T | 적을 제거하고 높은 길을 걸어 보는 탐험 모드 |
| WASD / Space / J | 화면 기준 이동 / 회피 / 기존 직접 공격 |
| B / Esc | 자동 공격 전환 / 종료 |

카메라는 pitch52°, size26 고정이다. 전투에서는 같은 월드 지점을 바라본다. 탐험에서는 플레이어를 따라간다. 표시되는 주인공은 승인 정지8방향이며 새 이동·공격 작화는 별도 작업이다. 적과 VFX는 기존 임시 미술이다.

## 비용을 줄인 구현

- 기존 Landscape region1의 곡선형 단차·경사로, Player 물리, 적 AI, 충돌, 공격 경고, Combat, 효과를 재사용했다. 새 AI나 다층 엔진을 만들지 않았다.
- 지형 렌더·충돌·이동·공격 경고가 동일 Landscape 높이/삼각형을 사용한다. 기존 map_preview의 별도 높이를 전투에 억지로 연결하지 않았다. 따라서 이번 비교 성공을 물길/제단 맵의 전투통합 완료로 해석하면 안 된다.
- 기존 환경 PNG3장 중 식생과 지면 재질을 재사용. 신규 이미지 생성0회, 신규 외부 API 요청0회(문서조회 제외). 카메라마다 별도 맵/원화를 제작하지 않았다.
- Player의 입력을 선택적으로 변환하는 접점3줄만 공통 파일에 추가. 기본 장면에는 기존 입력을 그대로 사용한다. 비교용 하위 클래스가 카메라 기준 방향·캐릭터 카드·적 표시를 맞춘다.
- 석조는 실제 메시, 식생은 카메라 방향에 맞춘 카드. 재사용에 적합하지만 건축물 전체를 한 장의 그림으로 만들면 시점별 일관성을 잃기 쉬우므로 피한다.
- 오른쪽 진입은 기존 경사로에 접지한 포석이다. 새18단 계단이나 다리 아래 보행을 구현한 것으로 표시하지 않는다.

## Sol 아주 높음 기준 판단

고정 시점 하나, 단일 높이 지형, 출입구 연결 맵, 공통 전투 계약, 소수 환경 부품이라는 범위는 이어서 제작하기에 적절하다고 판단한다. 이는 모델 성능 벤치마크가 아니라 코드의 영향 범위와 재작업 위험에 따른 평가다. 더 높은 추론 설정만으로 원화 일관성·모션 자연스러움·사람 체감 검수가 해결되지는 않는다.

| 후속 작업 | 상대 난이도·재작업 부담 | 운영 방식 |
|---|---|---|
| 이번 비교장 수치·배치 조정 | 낮음 | 동일 장면, 같은 검사·캡처 재사용 |
| 시점 확정 후 환경 부품 정리 | 중간 | 석축/경사로/식생 몇 종류부터 검수 |
| 기존 물길·제단을 공통 전투 지형으로 통합 | 중간~높음 | 높이·경고·표적·리스폰을 한 묶음으로 검수 |
| 24마리 겹침·경고 혼잡 개선 | 중간~높음 | 군중 위치/경고 정책 검토 후 실제 AI 성능·가독성 검사 |
| 콘셉트 그림 수준의 전 지역 완성미술 | 높음 | 원화 생성보다 부품 분리·연결·반복 제거·픽셀검수 부담 큼 |
| 다리 위아래 동시 보행·층간 전투 | 높음 | 단일 높이 계약을 넘어 표면/층 식별·경로·판정 필요; 초기 범위 제외 권고 |

무제한 ‘완성까지 계속’보다 `같은 재현 장면 → 한 원인 수정 → 필요한 회귀 → 실제 화면` 단위로 진행한다. 기능이 통과한 뒤 같은 검사를 이유 없이 반복하거나, 시점이 정해지기 전에 그림을 대량 생성하지 않는다. 한 작업의 토큰·시간을 보장할 근거는 아직 없다.

## 금전 비용과 사용량

2026-09-24 확인한 [OpenAI 공식 Codex 요금 문서](https://learn.chatgpt.com/docs/pricing)는 GPT-5.6 Sol Standard에서 백만 토큰당 입력100 / 캐시입력10 / 출력500 credits를 안내한다. 구독 포함 사용량은 이 수치만으로 결정되지 않으며 문맥·추론·도구·캐시가 영향을 준다. ‘아주 높음 한 번 = 얼마’라는 고정 단가는 아니다.

[공식 API 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-sol)의 입력 $4 / 캐시입력 $0.40 / 출력 $20 per 1M tokens는 API 직접 사용 기준이다. 앱 구독에 그대로 적용하지 않는다. 장문·속도·도구·이미지 비용은 별도 조건이 있을 수 있다.

실제 이 작업의 Sol 토큰 사용량을 측정하지 않았으므로 작업당 원화 금액·남은 횟수·완성 일정은 산출하지 않는다. 현 단계에서 확실한 절감은 새 그림을 만들지 않고 한 장면·기존 계약·같은 테스트를 재사용한 것이다.
