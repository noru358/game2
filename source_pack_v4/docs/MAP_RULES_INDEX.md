## 1. 먼저 볼 결론

실제 제작안은 [숲 유적 기본안01](maps/FOREST_REGION_DIRECTION.md)의 여섯 결정(구도·축척·구조·표현·주변 배경·지역 관계)과 동일 구도 시험 화면을 함께 본다. 철학 문구를 더 늘리는 대신 실행값과 미확정 범위를 그 문서에 둔다.

**단순하고 읽기 쉬운 구조를 만들고, 재료·식생·빛·장소의 배치로 풍부하게 표현한다.** 네모나 격자를 결함으로 취급하지 않는다. 도구와 규칙은 디자인을 돕는 수단이며 새로운 디자인을 금지하는 틀이 아니다.

| 구분 | 적용 범위 | 변경 방식 |
|---|---|---|
| 경험 원칙 | 읽히는 동선·전투, 장소의 인상, 감당 가능한 제작비 | 방향을 바꿀 때 사용자와 재논의 |
| 시각 방향 | B′ 클린 2.5D, 큰 형태, 조용한 플레이 바닥 | 기준 이미지와 실제 화면 비교 |
| 기술 계약 | 지면·충돌·발·AI·경고·저장의 일치 | 필요하면 확장하되 관련 회귀 검사 |
| 맵별 선택 | 모양, 높이, 동선, 랜드마크, 밀도, 연출 | 해당 장소에 맞춰 결정 |
| 생산 예산 | 부품 수, 고유 자산 수, 디테일과 작업량 | 실제 결과와 비용에 따라 조정 |

## 2. 지형과 공간

| 항목 | 현재 기준 | 고정하지 않는 것 |
|---|---|---|
| 기본 구조 | 이번 숲 유적은 평평한 직사각 단구·직선 석축·낮은 수로·계단 | 모든 지역을 똑같은 사각 마당으로 복제하지 않음 |
| 자연스러움 | 재료의 변화·식생 군집·국소 파손·빛·구조와 뿌리의 관계 | 곡선/비대칭 의무 없음. 필요한 곡선은 허용 |
| 높이 | 윗면과 옆면, 접근 가능한 연결을 명확하게 표현 | 모든 맵의 층수나 높이차를 통일하지 않음 |
| 이동 | 실제 속도·회피 폭에서 연결과 목적지가 읽힘 | 갈림·재합류·지름길 필수 아님 |
| 전투 공간 | 적과 경고, 회피 여백이 읽힘 | 직사각/원형 자체를 합격·불합격 사유로 삼지 않음 |
| 장소 차이 | 배치·시야·활동·재료·랜드마크의 관계로 구분 | 모든 지역에 완전히 새로운 토폴로지 강요 안 함 |
| 전망/랜드마크 | 방향과 장소 인상을 돕게 사용 | 매번 가렸다 재노출하거나 화면당 1개일 필요 없음 |
| 화면과 맵 | 실제 카메라는 연속 맵의 일부를 따라감 | 컨셉 한 장을 반드시 전체 맵 또는 단일 화면으로 고정하지 않음 |

## 3. 카메라·캐릭터·미술

- 높은 고정 사선 정사영 2.5D가 현재 방향. 플레이 중 자유 회전은 도입하지 않는다.
- yaw 20°가 품질을 보장하지 않는다. pitch/yaw/zoom의 최종 조합은 미확정이다. 기존 52°/0°, 실험 60°/20°, 신규 시험 55°/30°는 서로 다른 실행값이지 동시 적용할 규칙이 아니다.
- 카메라 pitch는 바닥/옆면의 비율, orthographic size는 보이는 범위와 캐릭터 크기에 영향을 준다. 카메라 위치만 높여 해결한다고 가정하지 않는다.
- 화면 기준 이동과 8방향 표현을 유지한다. 시점 변경 시 발 접점·방향·투영 크기를 함께 검사한다.
- B′ 클린 2.5D: 깨끗한 실루엣, 큰 명암 덩어리, 절제한 질감. 저폴리 임시물이나 사진 같은 고주파 묘사를 최종 기준으로 삼지 않는다.
- 플레이 바닥은 조용하게, 통행 경계는 분명하게, 주요 구조물은 필요한 만큼 풍부하게. 밀도를 모든 곳에 동일하게 배분하지 않는다.
- 따뜻한 석재/녹색 식생/억제된 청록 물은 첫 숲의 팔레트다. 모든 지역의 강제 팔레트가 아니다.
- 승인 주인공 원화가 외형 기준이다. 배경 참고 속 캐릭터·적·UI는 제외한다. 미승인 보행 자산을 승인 상태로 보고하지 않는다.
- 기본 창 1152×720에서 주인공 약74px는 비교 기준이다. 모션·투명 여백에 따라 실루엣은 달라지며, 조감에서는 작아진다. 배경이 복잡하다고 캐릭터만 몰래 확대하지 않는다.
- 접촉 그림자, 광원 방향, alpha 가장자리, 전경 가림을 실제 크기로 확인한다. 모든 식생에 같은 반전/스케일을 무조건 허용하지 않는다; 광원과 형태가 깨지면 별도 변형이 필요하다.

## 4. 첫 숲 맵에만 해당하는 결정

**물가 입구 → 굽이치는 강가 → 뿌리 성소**는 전체 지역 관계를 먼저 정한 뒤 이어 만드는 1·2·3구역 맵이다. 한 덩어리를 삼등분하지 않는다. 구역별 크기·내부 배치는 다를 수 있고 수로·높이·출입 방향·배경이 연결된다. 로딩 방식은 미확정이다.

| 구간 | 원하는 경험 | 제작 해석 |
|---|---|---|
| 물가 입구 | 신비롭고 성스러운 유적에 들어감 | 물·석문·석조 접근부로 문턱을 표현 |
| 굽이치는 강가 | 강을 따라 성소로 올라가는 주경로 | 선택 구간이 아님. 방향 전환은 직각 굽이도 가능. 단구/계단으로 상승 |
| 뿌리 성소 | 뿌리에 덮인 고대 동남아 성소에 도착 | 건축과 뿌리가 얽힌 큰 형태, 접근부와 도착 공간 |

North Star v2는 구조·미술 방향의 기준이지 좌표 설계도가 아니다. 다만 정확한 좌표가 자유라는 이유로 석조 단구를 둥근 흙언덕으로 바꾸지 않는다. A/B 제작 시험은 이 세 구간의 최종 배치가 아니라 부품 재사용 시험이다. 첫 맵의 '강을 따라 이동'과 A/B의 '다리 횡단'도 혼동하지 않는다.

## 5. 만드는 방법 — 재사용은 권고, 새 코드 금지 아님

| 변경하려는 것 | 우선 수단 | 코드가 필요한 경우 |
|---|---|---|
| 마당 크기·높이·위치, 계단/수로 연결 | 맵 데이터/씬 편집 | 기존 표현 범위로 필요한 형상이 안 나올 때 생성기 확장 |
| 석재·식생·색·소품 | 자산과 재질/배치 설정 | 새 재질 효과나 가림 방식이 필요할 때 |
| 새로운 다리·문·승강기 | 공통 부품 추가 또는 전용 씬 | 동작/충돌/상태 전이가 필요할 때 |
| 특수 붕괴·보스 지형 연출 | 맵 전용 스크립트 허용 | 무리하게 모든 맵용 설정 언어로 만들지 않음 |
| 다리 위/아래 동시 통행 | 현재 단일 높이 계약 밖 | 층 식별·AI·경고·저장까지 설계 확장 후 구현 |

‘매번 다시 깎지 않는다’는 같은 바닥/충돌 알고리즘을 복제하지 말자는 뜻이다. 새로운 디자인의 코드를 막거나, 기존 도구에 맞춰 맵을 억지로 바꾸라는 뜻은 아니다. 재사용을 위해 과도한 범용 엔진을 먼저 만드는 것도 피한다.

대표 구간 하나를 공들여 부품 품질을 잡고, 다른 배치에서 재사용해 본다. 두 번째에도 필요한 고유 자산/코드는 추가할 수 있다. 무엇이 재사용됐고 무엇이 새로 필요했는지 작업량과 함께 기록한다. 모든 맵을 코드 추가 0줄로 만들어야 한다는 기준은 없다.

## 6. 기술 안전 계약

- 보이는 바닥, 충돌, 높이 조회, 발/그림자, 적과 경고, 리스폰/저장이 같은 지형을 가리켜야 한다.
- 기존 Landscape의 단일 불투명 표면/paving 계약은 기존 게임의 회귀 보호 장치다. 새 구조에서 바꿀 수 없다는 영구 미술 법칙은 아니다.
- 새 ruin 시험은 상부/측면 메시와 낮은 별도 불투명 수면을 사용한다. 기존 단일 표면과 다른 실험임을 명시한다. 겹치는 동일 높이 overlay는 없지만 해안 경계·깊이·수역 진입과 경고 등 검증이 필요하다. 본게임 계약 전환 완료가 아니다.
- 기본 진입점/운영 저장을 시험용으로 바꾸지 않는다. 독립 --test 사용. 맵 전환 통합 시 안정적 map/entry/object ID와 왕복·복원 검증이 필요하다.
- 배경 한 장을 충돌 위에 얹는 방식은 현재 주 제작 방식이 아니다. 구조는 3D, 식생/캐릭터 등은 필요한 카드와 메시 혼합.

## 7. 작업 순서와 합격 기준

1. 컨셉/기준 화면과 플레이 목적 확인. 이미 방향이 잡혔다면 전체 시안 미화 반복은 중단.
2. 맵별 동선·높이·주요 장면과 필요한 부품 정의. 그림과 구조 설계를 서로 조정할 수 있음.
3. 대표 구간에서 실제 크기/카메라/이동과 환경 자산을 확인. 회색 검사와 미술 검사는 분리하되 왕복 가능.
4. 자동 검사와 실제 GPU 화면 비교. 기능 통과를 시각 통과로 대신하지 않음.
5. 다른 배치로 재사용 시험. 새 코드/자산/수정 횟수와 비용 기록.
6. 사용자 화면·조작 검토 후 확장. 첫 숲 전체와 본게임 통합은 별도 완료 조건.
