# D107 — 실제 전투의 프레임 정지 수정

2026-09-22. 현재 **P1 검증/P2 제작, M1-A 전투 기본 품질**. 최종 목표는 본편 Steam 출시와 초기 안정화다. 이번 작업은 약10분 데모의 전투를 정상적으로 검증할 수 있게 만드는 작업이며, 분량 확장이나 데모 완성 선언이 아니다.

## 원인과 변경

사용자가 적이 적어도, 특히 몰아서 사냥할 때 플레이하기 어려울 정도의 렉을 재보고했다. D106은 처치마다 동기 저장하는 병목을 고쳤지만, 당시 성능 검사는 적 AI/물리 처리를 꺼서 다른 큰 병목을 놓쳤다. 당시의 ‘큰 끊김 원인은 파일 쓰기’ 설명을 전체 전투에 대한 결론으로 해석하면 잘못이다.

실제 적은 공격 준비 중 매 물리 틱마다 같은 예고선 메시를 다시 만들었다. 64개 구간×3개 띠의 중복 꼭짓점마다 지형 높이/법선을 여러 번 구하고, 중심의 경사도 계속 다시 구했다. 원 하나에서 수만 번의 원시 높이 계산이 발생했다. 여러 적이 동시에 준비하면 물리 틱 예산을 초과하고, 밀린 틱의 연속 처리로 화면이 수초씩 멎었다.

- `ground_warning.gd`: 중심·반경·방향·변환·지형 모드·색이 같으면 메시 재사용. 바뀌는 시전자/수호자 원은 계속 갱신한다. 공유 꼭짓점은 한 번만 판정하고 PackedArray를 ArrayMesh로 한 번에 제출한다. 64구간·3개 띠·급단차에서 끊기는 기존 기하/판정은 유지한다.
- `effect_surface.gd`: 예고선의 기준 평면을 한 번 구해 공유한다. 경사면에 전체 효과를 다시 구부리는 방식으로 돌아가지 않는다.
- `landscape.gd`: 지형 단위 셀의 네 높이를 재사용하고 같은 삼각형의 법선을 바로 계산한다. 지역/평지 모드가 바뀌면 캐시를 비운다. 렌더·충돌·발견·카메라·복귀가 사용하는 높이 결과는 변경하지 않는다.
- 적 수/AI/공격 빈도/피해/체력/범위/게임 속도는 줄이지 않았다. 원본 D95와 이전 실행본은 보존했다.

## 실제 전투 비교

RTX 4060 Ti, Windows, OpenGL Compatibility, 제한 60 FPS. 별도 `--test` 프로세스, 고유 PID 저장 파일. AI·플레이어·월드 물리는 모두 켜고 직접 입력/자동 공격/음향/주기 저장을 실행했다. 플레이어 무적과 적 고체력은 반복 측정을 위한 조건이며 난이도/플레이 시간 검증이 아니다. 각 조건 최대240프레임 또는12초. 프레임은 벽시계 시간, 물리는 시작/끝 우선순위 프로브로 측정한다.

| 살아 있는 적 수 | 기존 0.8 최대 프레임 지연 | 최종 0.9 최대 지연 | 최종 0.9 p95 |
|---|---:|---:|---:|
| 2 | 84.777ms | 18.890ms | 17.853ms |
| 8 | 904.114ms | 26.896ms | 18.616ms |
| 24 | 2398.701ms | 21.335ms | 19.086ms |

기존 0.8의 8/24 조건은 12초 제한으로 각각110/9프레임만 수집했다. 최종 0.9는 조건별240프레임을 수집했다. 같은 프레임 개수의 장시간 통계라고 해석하지 않는다. 최종 평지24 물리 콜백 p95 7.077ms, 최대12.089ms. 증거: `validation/d107/baseline-08`, `verified-flat`.

추가 실제 전투 검증:

- 정글 경사면, 근접/돌진/원거리 혼합24: p95 18.550ms, 최대20.279ms. `verified-jungle`.
- 사원 혼합24+수호자1, 수호자 경고 실제72프레임: p95 18.236ms, 최대21.436ms. `verified-guardian`.
- 사원 일반 체력의 실제 연속 사냥/좌우 이동: 각2/8/24 조건에서 실제2/8/10마리 처치. 저장과 처치 효과 포함, p95 최대19.223ms. 전체 조건 중 단발 최대40.303ms는 남았다. `verified-hunt`.
- 최종 위 조건은 포커스 일시정지 제외 횟수0. 장시간·다른 PC·사람의 조작감은 아직 미검증이다.

## 계약 및 화면 검수

- `warning_cache_contract`: 비캐시 원래 높이/법선과 지역 왕복 비교, 원래 예고 원/돌진 띠의 모든 삼각형·단차 잘림 비교, 60틱 재사용, 반경/변환/지형 변경 시 무효화 통과.
- ground_surfaces, terrain_probe, grounded_run, exploration, warning_damage, lab_contract, lab_flow, lab_combat, lab_growth, strike_range, moving_strike, diagonal_strike, lookout_contract, threshold_contract, save_queue_contract, keyboard_choices 통과.
- journey_routes 실제 입력의 3구간 왕복/발견/종료 통과. 이 검사는 적을 정지시키므로 위 실제 전투 검사와 구분한다.
- 최종0.9 실행본 journey_flow: 이동·성장·저장·새 장면 복귀·결말 통과. 정상 저장의 정글 복귀를 GPU에서도 확인했다.
- 최종 실행본 slope_cues 4지점, render_surface_motion 14지점×24시점 통과. 정원 오른쪽/빗물길/석문/쉼터와 경사면의00/23 캡처를 실제 픽셀로 비교했다. 검사된 쌍에서 새 표면 겹침·예고선 변형은 관찰하지 못했다. 최종 미술 품질 승인은 아니다.

## 검사 중 실패/정정

- 최초 하네스는 입력 이름을 `strike`로 잘못 썼다. 해당 실행을 중단하고 실제 `pulse`로 고쳤으며 그 실행은 성능 근거에서 제외했다.
- 초기 `after`는 느린 baseline24 프로세스와 일부 겹쳤다. 최종 수치는 프로세스를 하나씩 실행한 `verified-*`만 사용한다.
- 초기 `final`의24 조건은 창 포커스 상실로 일시정지되어 물리 표본이 없었다. 이를 통과로 쓰지 않고 자동 복귀/제외 기록 및 실제 물리·공격 실행 검사로 수정했다.
- 초기 지역 테스트는 `journey_restore`에 chapter만 넣은 불완전한 가짜 저장으로 실행하여 내보낸 실행본이 종료코드 -1073741819로 실패했다. 필수 player/enemies/schema를 갖춘 실제 저장 경로가 아니었다. 테스트를 정상 `travel()`로 변경했고, 완전한 저장 복귀는 journey_flow에서 따로 통과했다. 제품 Store 읽기는 해당 필수 필드를 검증한다. 이 실패를 정상 저장 손상 수정으로 기록하지 않는다.
- 첫 캐시 검사 스크립트의 타입 추론 오류를 수정하고 다시 통과했다. 최종 검수 stderr는 비어 있다.
