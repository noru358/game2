# 맵 구도 블록아웃 v1 — 시각 목표에서 제외

> 2026-09-25 정정: 사용자가 요청한 것은 이 플레이 가능 블록아웃이 아니라, 완성 게임 화면을 상정한 배경·맵 컨셉 시안이었다. 이 장면은 기능 실험 기록으로만 남기며 시각 North Star, 승인 시안, 후속 자산 제작 기준으로 사용하지 않는다. 후속 논의 기준은 `docs/design_refs/map_concept_v1/README.md`다.

2026-09-24 제작 당시에는 `지형·시야·이동·전투·발견이 하나의 공간적 아이디어를 표현한다`는 원칙을 실제 장면에서 검토하기 위한 독립 composition proof로 만들었다. 그러나 컨셉→문법→기초 자산→한 화면 구현이라는 사용자 의도보다 엔진 구현을 앞세운 잘못된 순서였다.

- 실행: 작업공간 `PLAY_COMPOSITION_PROOF.cmd`
- 기본: yaw20°, pitch52°, 전체 구도, 전투 정지.
- 조작: `1/2/3` yaw15/20/25, `Tab` 전체/플레이, `F` 전투 정지·재개, `R` 같은 전투, `T` 탐험, `WASD/Space/J` 기존 이동·회피·직접공격.
- 구조: 전면 수면과 진입섬·사선 다리, 중앙의 넓은 전투 지형, 실제 계단으로 연결되는 후면 고지 사원. 같은 위치에 겹치는 보행층은 없다.
- 기존 환경 atlas와 전투 시스템을 재사용한다. 새 이미지 생성은 없고, 첨부 시안은 `docs/design_refs/environment_composition_concept.png`에 구도 참고로 보존한다.
- 캡처: `01_framed_20.png` 전체 구도, `02_gameplay_20.png` 실제 플레이 크기, `03_yaw_15.png`/`03_yaw_25.png` 각도 비교, `04_upper_arrival.png` 상부 도착, `05_live_combat.png` 실제 전투.

## 검증 결과

- 전용 검수: headless 25 PASS / 0 FAIL, GPU 31 PASS / 0 FAIL.
- 실제 물리 입력으로 중앙→다리→진입섬→복귀, 중앙→계단→상부 사원 도착을 확인했다.
- 실제 적·자동/직접 전투와 경고 표면이 새 지형 높이를 따르는지 확인했다.
- 전투 밀치기로 물에 떨어지지 않도록 보이는 절벽 경계와 같은 위치에 안전 경계를 두었다. 다리와 계단 진입부는 열려 있다.
- 공용 표면 계약 회귀: `warning_damage` 8, `core_response` 6, `lab_contract` 10 PASS. GPU `slope_cues` 12 PASS. 헤드리스 `slope_cues`는 렌더 프레임 대기 특성상 완료되지 않으므로 GPU 결과를 사용했다.

## 실제 화면 판단과 남은 것

큰 지형 덩어리, 전면 수면/다리, 중앙 전투 포켓, 후면 고지 사원의 전후 관계는 이전의 굽은 선형 길보다 명확하다. 다만 이것은 **구도 시안**이며 최종 환경 미술이 아니다. 사원은 블록형 모듈, 계단은 멀리서 넓은 경사판처럼 읽히고, 중앙은 아직 비어 있으며, 외곽은 큰 수면 위 섬처럼 보인다. 첨부 시안의 세부 묘사·건축 완성도·식생 밀도를 달성했다고 보지 않는다.

이번 사용자 검토는 우선 `큰 덩어리의 관계`, `중앙 전투 공간의 크기와 위치`, `진입섬→중앙→고지 사원의 이동 장면`이 맞는지를 본다. 기능 통과를 미술 승인이나 사용자 수용으로 간주하지 않는다.
