# 실제 맵 캐릭터 검수장

승인 원화 8방향을 기존 이동·충돌·카메라 위에서 직접 비교하는 독립 장면이다. **8방향 원화에 엔진 메시 변형을 적용한 1차 이동 모션이다. 별도 작화된 최종 보행 모션은 아니다.** 일반 게임 진입점은 그대로다.

Godot 4.7.2로 실행:
```powershell
& 'Godot_v4.7.2-stable_win64_console.exe' --path experiments/terrace res://lab/hero_art_playground.tscn -- --test
```
소스팩 루트에서 실행한다. --test 없이는 저장을 읽기 전에 종료한다. 실제 저장과 전투는 사용하지 않는다.

- WASD/방향키: 이동. Space: 기존 회피.
- V: 승인 원화와 기존 임시 캐릭터 비교. M: 이동 모션 켜기/끄기. F: 선명/밉맵 필터 비교. Z: 원래 시야/확대 검수.
- 1/2/3: 실제 세 지역. R: 중앙 시작점. Esc: 종료.
- T: 식물 가림 완화 비교. 화면에서 겹치는 식물을 20% 불투명도로 낮추고 벗어나면 복원한다.

식물 검사는 캐릭터 발 기준 깊이와 화면상 네 높이의 알파를 이용한다. 같은 깊이 부근의 투명 카드 정렬을 고려한 0.75u 허용폭이 있는 근사다. 나무 전체가 옅어지며 바위·벽은 그대로다. 모든 모양의 가림을 해결했다고 보지 않는다.

검증: tests/hero_art_playground.gd가 실제 플레이어 물리를 실행하여 세 지역 × 8방향, 정지, 가속, 비교, 식물 가림과 복원을 검사한다. PNG는 실제 GPU 화면이다. 신체가 나무 뒤에서 드러나는 개선은 확인했으나 바위 앞에서는 하체가 가려질 수 있다. 정면·후면은 양쪽 하체를 반대 위상으로 변형한다. 옆모습은 원화에 보이는 한 다리만 움직이며, 숨은 다리/팔의 별도 작화와 지지발 미끄러짐 해결은 남아 있다.

다음 제작: 빠른 이동에 맞는 달리기 접지·발교대 → 대표 4방향 소량 모션 → 최종 8방향 → 전투 동작과 통합 구간. 정적 8방향이 있다는 이유로 이 단계를 완료 처리하지 않는다.

## 이동 모션 1차와 화질 확인
- `lab/hero_locomotion.gd`와 shader: 원본 PNG를 변경하지 않는 32×48 메시 변형. 실제 이동 거리로 위상 진행, 정지 0.083초 이내 감쇠, 리셋/순간이동 제외, 회피 시 발 구르기 억제와 기울임. 방향 원화 8개를 그대로 사용하며 좌우 반전 재사용 없음.
- 보이는 발·옷자락·몸 반동을 연동했다. 전체 몸만 상하로 움직이는 정적 전환에서 진전했지만, 두 다리의 새로운 실루엣이나 손·꼬리 독립 리그는 없다. 최종 모션으로 채택한 상태가 아니다.
- 화질을 새 배경에 맞춰 낮춘 결정은 없었다. 새 그림은 기존과 달리 밉맵 필터를 썼고 기본은 linear로 맞췄다. 다만 GPU 비교에서 여전히 기존 그림이 더 또렷하다. 새 원화의 큰 머리·귀, 가는 장식·윤곽과 약74px 표시에서의 정보 손실이 남는다. 원본 세로 약460px는 기존 약440px보다 작지 않으며 JPEG 재압축도 없다.
- [화질 비교](quality_old_mipmap_linear.png): 왼쪽 기존, 가운데 새 밉맵, 오른쪽 새 linear. 같은 카메라·표시 높이. 확대 검수는 Z이며 새 배경/최종 카메라 변경으로 확정하지 않는다.
- [8방향 네 위상](motion_contact_sheet.png): 행은 RIGHT,FRONT-RIGHT,FRONT,FRONT-LEFT,LEFT,BACK-LEFT,BACK,BACK-RIGHT. 열은 0/25/50/75% 주기. 픽셀 차이 검사는 자연스러움·발 고정의 증명이 아니다.
- `tests/hero_locomotion_review.gd`: 거리·정지·순간이동·회피·M/F/Z·8방향 GPU 차이·2초 연속 위상 검사. `motion_qa.json`에 결과.
